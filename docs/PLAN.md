# 虚拟头像设计系统 · 实施计划书 v2

依据《虚拟头像设计系统 · 项目说明与六人分工》v1.0（2026-11-13）整理。仓库以本文为准，
旧版计划（M0–M6、A–F 分工、FastAPI）已由 [迁移说明](MIGRATION-v2.md) 标注为历史。

## 0 摘要

一个双路径虚拟头像设计系统：**上传照片自动生成**，或**完全不上传照片的捏脸编辑**。
两条路都收敛到同一份「配方（Recipe）」JSON，由确定性的分层渲染引擎合成 256 / 1024 的透明 PNG；
配方可存库、可分享、可二次编辑。

## 1 对标产品拆解

| 维度 | 市面上常见做法 | 我们的取舍 |
| --- | --- | --- |
| 输入 | 只做 AI 生成，必须上传照片 | 双路径：照片估计 + 手动捏脸，隐私友好 |
| 结果 | 不可复现、不可编辑 | Recipe 确定性渲染，随时重放 |
| 分享 | 只能发一张图 | 配方编码进链接，别人可在此基础上改 |
| 素材 | 平台私有 | 目录即素材库，加图零代码改动 |

## 2 目标与非目标

### 2.1 本期目标

1. 捏脸路径闭环：点选、实时预览、换色、随机、下载 256/1024。
2. 照片路径：YuNet 检测并裁剪人脸，只推断肤色、发色、眼镜/帽子有无、表情倾向；发型给候选不硬猜。
3. 配方可存、可分享、可复现（SQLite + URL）。
4. 6 套预设模板 + 随机生成。
5. 工程闭环：pytest 全绿、素材校验零报错、README 三步跑通。

### 2.2 非目标

- 3D 可旋转头像；实时生成式 AI；账号体系与社交关系；自训人脸解析大模型；移动 App。

## 3 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | Flask 3 + Jinja2 | 对应课程案例 2，轻量易演示 |
| 数据 | SQLite + sqlite3 | 对应案例 1，零部署、单文件 |
| 图像 | Pillow + numpy | 合成、缩放、快照比对 |
| 视觉 | OpenCV（YuNet 人脸检测）+ 预训练特征 + scikit-learn | 模型 340 KB，CPU 秒级；训练分钟级 |
| 前端 | 原生 HTML/CSS/JS | 无构建链，降低协作成本 |
| 测试 | pytest + Flask TestClient | 契约、快照、素材校验 |

视觉方案说明：人脸检测用 OpenCV 自带的 **YuNet**（`face_detection_yunet_2023mar.onnx`，约 340 KB，
CPU 单张毫秒级），属性分类用 CelebA 子集 + scikit-learn 线性模型。
不引入 torch / ultralytics：三周周期内，模型体积、安装失败风险与收益不成比例；
课程案例 3 的 YOLO 方案作为对照写进报告，说明取舍。

## 4 系统架构

```
① 表现层  HTML/CSS/JS（捏脸编辑器 / 结果页 / 作品页）
② 接口层  Flask：manifest / render / analyze / works / share
③ 业务层  配方校验 · 兼容性检查 · 随机生成 · 预设模板
④ 能力层  渲染内核（Pillow） │ 视觉分析（YuNet + sklearn）
⑤ 数据层  assets/（素材库） · SQLite（作品与配方）
```

数据流：前端 state（Recipe 草稿）→ `POST /api/render {recipe, size}` → 校验 → 合成 → `image/png`。
照片路径多两段：`POST /api/analyze` → 质量门控 → 对齐 → 取色 → 属性分类 → Recipe + 置信度。

## 5 数据模型

### 5.1 Recipe

```json
{
  "schema": 1,
  "slots": {
    "skin": "skin_base", "clothes": null, "hair_back": null, "hair": "hair_straight_01",
    "eyes": "eyes_round_01", "brows": null, "mouth": "mouth_smile_01",
    "glasses": null, "hat": null, "extra": null
  },
  "colors": { "skin": "#E8B98A", "hair": "#2B1B12" },
  "meta": { "seed": 20261113 }
}
```

铁律：渲染函数是纯函数，同一份 Recipe 永远产出同一张图。

### 5.2 数据库

```sql
CREATE TABLE works (
  id          TEXT PRIMARY KEY,
  session_id  TEXT NOT NULL,
  title       TEXT NOT NULL,
  recipe_json TEXT NOT NULL,
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_works_created ON works(created_at DESC);
```


## 6 素材规范

| z | 槽位 | 说明 | 本期 |
| --- | --- | --- | --- |
| 10 | skin | 脸型底，肤色靠取色 | 启用 |
| 20 | clothes | 服装，压在肩上 | 启用 |
| 25 | hair_back | 后发，压在服装与脸之间 | 启用 |
| 30 | hair | 前发（刘海），压住额头 | 启用 |
| 40 | eyes | 眼睛（线稿，颜色固定） | 启用 |
| 45 | brows | 眉毛 | 启用 |
| 50 | mouth | 嘴 | 启用 |
| 60 | glasses | 眼镜，压五官 | 启用 |
| 70 | hat | 帽子，最上层压头发 | 启用 |
| 80 | extra | 耳饰、贴纸等兜底 | 启用 |

素材预算：

| 槽位 | 数量 | 内容 |
| --- | --- | --- |
| skin | 17 | 美式卡通 2 + 手绘线稿 4 + 像素方块 3 张脸 + 8 个整身形象 |
| hair | 26 | 美式卡通 15 + 手绘线稿 5 + 像素方块 6 |
| eyes | 36 | 美式卡通 24 + 手绘线稿 8 + 像素方块 4 |
| brows | 11 | 美式卡通 4 + 手绘线稿 4 + 像素方块 3 |
| mouth | 29 | 美式卡通 17 + 手绘线稿 8 + 像素方块 4 |
| glasses | 12 | 美式卡通 5 + 手绘线稿 4 + 像素方块 3 |
| 合计 | 131 | 三套风格，只统计面部槽位 |

另有 **18 张像素小装饰**（`extra` 槽位：小动物 / 水果 / 花朵 / 天气），不计入面部预算，素材总计 **141 张**。

素材规格：1024×1024、RGBA、透明背景，命名 `<槽位>_<形状>_<两位序号>.png`，单张 ≤ 80KB。
对齐基线：头顶 y=170、眼睛 y=460、脸中心 y=500、嘴 y=620、肩线 y=880。
可着色素材 = 白色基色 + 灰度明暗 + 黑描边；眼镜与配饰直接上色。

## 7 API 契约

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| GET | `/api/manifest` | — | schema、slots、default_recipe |
| POST | `/api/render` | recipe、size | image/png |
| POST | `/api/analyze` | multipart 图片 | recipe、confidence、notes |
| POST | `/api/works` | title、recipe | id |
| GET | `/api/works` | — | 作品列表 |
| GET | `/api/works/<id>` | — | 单个作品 |
| GET | `/healthz` | — | ok、version、assets |

错误结构：`{"error": {"code": "BAD_SIZE", "message": "size 只能是 256 或 1024"}}`。
错误码至少包含：`BAD_SIZE`、`UNKNOWN_ASSET`、`INVALID_REQUEST`、`NO_FACE`、`MULTI_FACE`、
`FACE_TOO_SMALL`、`BLURRY`。

## 8 渲染管线

渲染四步：按 z 序取层 → 可着色层白底乘目标色（保留明暗与描边）→ `alpha_composite` 合成 →
`LANCZOS` 缩放 → PNG bytes。必须用 `alpha_composite` 而不是 `paste`。

前端三栏：左侧分类导航、中间 1:1 实时预览、右侧颜色与操作。
每次选择立即重渲染（去抖 + 请求序号防止闪回旧图）；提供预设模板、随机、重置、下载、复制分享链接。
移动端 375 像素单列，触控目标 ≥ 44px。
